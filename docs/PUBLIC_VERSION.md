# 本来の機能と公開デモの違い

| 機能 | 元の実装が行うこと | 公開版 |
| --- | --- | --- |
| 会話の翻訳 | 発話を翻訳し、字幕として表示・相手へ共有 | 翻訳スイッチと自動開始を停止 |
| メッセージ翻訳 | 指定言語に翻訳し、表示・キャッシュ | 呼び出しを停止 |
| AI要約 | 字幕ログからレッスン内容・課題を整理し、先生専用記録へ保存 | 呼び出しを停止。サンプル記録は手書き |
| 先生のメール認証 | パスワード確認後に認証コードを送信・検証 | 省略。デモボタンで入れる。サーバー側のパスワード確認とJWTは維持 |
| 生徒の初回設定 | 名前・生年月日・性別・タイムゾーンを登録 | 省略。架空アカウントで入れる |
| 外部決済 | Stripeの接続、決済、Webhook、返金 | 停止。無料メニューで予約 |
| 実メール・Web Push | メール配送とブラウザ通知 | 設定を持ち込まない。メール配送は停止 |
| 会話・教材・予約 | アプリ内の操作と保存 | 専用ローカルDBと架空データで使用 |
| 通話 | WebRTCで映像・音声を送受信 | 実装を保持。機器・ネットワークごとの確認が必要 |

元のAI・認証コードは実装内容を読めるよう残しています。公開版では `PUBLIC_DEMO` とサーバーの応答を追加し、APIキーを設定しても翻訳・要約を動かさない構成です。直接リクエストしても `PUBLIC_DEMO_FEATURE_DISABLED` の501応答になります。ログイン画面の2つのボタンから、固定のデモ先生・デモ生徒1だけにログインできます。パスワードはブラウザに渡さず、専用ローカルDBとアカウントのID・役割を確認してからサーバー側で認証します。デモログインはメール認証の再現を目的としていません。

## 持ち込まないもの

- 元リポジトリの `.git` とコミット履歴
- 環境変数、認証情報、VPS接続情報、自動デプロイ・診断設定
- 実在の先生・生徒のDB、写真、教材、バックアップ
- 本番ドメイン、運用固有のメモ・ネットワーク図

公開版の氏名・会話・予約は架空です。固定パスワードをソースに書かず、セットアップ時にランダムな値を生成します。`.env`、アップロード、ログ、確認用データは `.gitignore` で除外します。

## 安全な初期化

`scripts/demo-environment.mjs` はローカルホスト、専用ユーザー、専用DB名を確認します。`db:setup` はマイグレーションと架空データの追加を行い、既存のデータやパスワードを削除・上書きしません。既存の `.env` もセットアップで上書きしません。

公開用の初期マイグレーションは、現在のスキーマから生成した1件です。元の運用用の移行手順を実行する必要はありません。
